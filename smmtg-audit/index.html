جمع‌بندی در یک نگاه

پایه‌های سئو (عنوان، توضیحات، canonical، hreflang، نقشه‌ی سایت) به‌خوبی چیده شده‌اند و این نقطه‌ی شروع خوبی است. مشکل اصلی جای دیگری است: صفحه‌ی اصلی روی موبایل حدود ۱۰٫۷ ثانیه طول می‌کشد تا کامل دیده شود، صفحه‌ی لیست قیمت ۶٫۸ مگابایت HTML دارد، نسخه‌ی http:// سایت جواب نمی‌دهد و تقریباً هیچ محتوایی برای کلمات کلیدی‌ای که مشتری واقعی جست‌وجو می‌کند (مثل «خرید ممبر تلگرام») وجود ندارد. با اصلاح این چند مورد، سایت هم سریع‌تر می‌شود و هم برای جست‌وجوهای پرمشتری فرصت رتبه گرفتن پیدا می‌کند.

سایت چه می‌کند و برای چه بازاری است

  • نوع سایت: پنل SMM برای فروش سرویس‌های شبکه‌های اجتماعی (ممبر، ویو، لایک، فالوور، استارت ربات و...) به کاربران و نمایندگان فروش، همراه با API.
  • سرویس‌ها: ۴۱۷ دسته و حدود ۶٬۹۰۰ سرویس. بیشترین دسته‌ها: تلگرام (۱۷۱ دسته)، اینستاگرام (۱۰۳)، یوتیوب (۵۱)، تیک‌تاک (۴۳).
  • زبان‌ها: انگلیسی (پیش‌فرض)، عربی، فارسی، روسی و هندی، با پارامتر ?lang=.
  • پرداخت: بیت‌کوین، USDT، Payeer، Perfect Money، ویزا، مسترکارت و Coinbase.
  • پلتفرم: فایل‌های قالب از cdn.officialrentalpanel.com بارگذاری می‌شوند، یعنی سایت روی یک پنل اجاره‌ای (Rental Panel) ساخته شده است. بعضی اصلاحات در قالب شما انجام می‌شوند و بعضی به دسترسی سرور یا ارائه‌دهنده‌ی پنل نیاز دارند. در لیست کارها مشخص کرده‌ام.

چیزهایی که درست انجام شده

  • عنوان و توضیحات متا برای هر صفحه و هر زبان جدا نوشته شده است.
  • canonical روی همه‌ی صفحات و hreflang دوطرفه برای ۵ زبان به‌همراه x-default وجود دارد.
  • robots.txt و sitemap.xml (۲۷ نشانی) سالم‌اند و صفحه‌ی بازیابی رمز noindex است.
  • نسخه‌ی www با 301 به نسخه‌ی اصلی می‌رود و صفحه‌ی ناموجود 404 برمی‌گرداند.
  • نسخه‌ی فارسی lang="fa" و dir="rtl" درست دارد. Accessibility در Lighthouse ۱۰۰ و Best Practices ۹۶ است.

صفحه‌ی اصلی روی موبایل خیلی کند است (امتیاز ۴۱)

بیشتر جست‌وجوهای این حوزه با موبایل انجام می‌شود. LCP روی موبایل ۱۰٫۷ ثانیه است. ۱۵ فایل CSS و فونت جلوی نمایش صفحه را می‌گیرند (حدود ۲ ثانیه تأخیر). reCAPTCHA (۳۵۶ کیلوبایت) و Google Sign-In (۱۰۳ کیلوبایت) روی صفحه‌ی اصلی بارگذاری می‌شوند، حتی اگر کاربر وارد نشود. جاوااسکریپت پنل حدود ۵۳۰ میلی‌ثانیه رشته‌ی اصلی مرورگر را قفل می‌کند. نسخه‌ی فارسی (?lang=fa) از این هم کندتر است: امتیاز ۴۲، FCP ۶٫۲ ثانیه و LCP ۱۲٫۲ ثانیه، و فقط فونت‌هایش ۳۶۷ کیلوبایت حجم دارند.

راه‌حل:
  • reCAPTCHA و Google Sign-In فقط وقتی بارگذاری شوند که کاربر روی فرم ورود کلیک کرد (lazy load).
  • jQuery دو بار بارگذاری می‌شود (code.jquery.com و نسخه‌ی پنل). یکی حذف شود.
  • Font Awesome و Remix Icon و flag-icon هر سه بارگذاری می‌شوند. فونت Remix Icon به‌تنهایی ۱۷۸ کیلوبایت است، برای حدود ۳۰ آیکون. بهتر است با SVG درون‌خطی جایگزین شوند.
  • Google Fonts چهار خانواده با ۵ وزن می‌گیرد. هر زبان فقط فونت خودش را بگیرد و ۲ یا ۳ وزن کافی است.
  • CSS و JS غیرضروری با defer یا media="print" onload از مسیر اصلی خارج شوند. Lighthouse حدود ۵۵۸ کیلوبایت JS و ۱۰۵ کیلوبایت CSS بلااستفاده گزارش کرده است.
شاهد: Lighthouse 12.8، موبایل با محدودسازی شبیه‌سازی‌شده‌ی شبکه، ۲۷ اکتبر ۲۰۲۶ ساعت ۱۷:۲۴ به وقت برلین. دسکتاپ: امتیاز ۸۶، LCP ۱٫۹ ثانیه.

تصویر اصلی بالای صفحه (LCP) حدود ۱۰ برابر سنگین‌تر از نیاز است

عنصر LCP صفحه‌ی اصلی تصویر /public/tg-plane.png است. این تصویر روی موبایل در اندازه‌ی ۱۲۰×۱۰۵ پیکسل نمایش داده می‌شود، ولی فایل اصلی ۶۸۶×۵۹۹ پیکسل و ۲۰۵ کیلوبایت است. لوگوی فوتر هم یک JPEG با ابعاد ۱۲۵۴×۱۲۵۴ و حجم ۱۰۸ کیلوبایت است، با پسوند png، و حداکثر در عرض ۱۷۰ پیکسل نمایش داده می‌شود.

راه‌حل: این تصاویر را خودم آزمایشی تبدیل کردم: تصویر هواپیما در عرض ۴۸۰ پیکسل (WebP) ۱۹ کیلوبایت شد (از ۲۰۵ کیلوبایت) و لوگو در ۳۴۰ پیکسل (WebP) ۸٫۶ کیلوبایت شد (از ۱۰۸ کیلوبایت). تصویر اصلی هم باید preload شود و اولویت بالا بگیرد: 
<link rel="preload" as="image" href="/public/tg-plane-480.webp" fetchpriority="high">
<img src="/public/tg-plane-480.webp" width="240" height="210" alt="SMM TG" fetchpriority="high">

صفحه‌ی لیست قیمت (Services) ۶٫۸ مگابایت HTML دارد

صفحه‌ی /services همه‌ی حدود ۶٬۹۰۰ سرویس را یکجا در HTML می‌فرستد: حدود ۱۹۳ هزار کلمه، ۴۱۷ تیتر H2 و ۶٬۸۹۷ تیتر H3. نسخه‌ی فارسی ۷٫۱ مگابایت است. Lighthouse در دو بار تست این صفحه هر دو بار به خطای timeout خورد، چون مرورگر نتوانست به‌موقع پردازشش کند. این مهم‌ترین صفحه برای کاربری است که می‌خواهد قیمت ببیند و خرید کند. روی موبایل‌های معمولی یا کند می‌شود یا کرش می‌کند، و برای گوگل هم صفحه‌ای است که موضوع روشنی ندارد.

راه‌حل:
  • صفحه‌ی Services فقط دسته‌ها را نشان دهد و سرویس‌های هر دسته با کلیک یا اسکرول بارگذاری شوند (lazy load با JSON).
  • برای پلتفرم‌های اصلی صفحه‌ی جدا ساخته شود: /services/telegram، /services/instagram، /services/youtube، /services/tiktok. هر صفحه عنوان، توضیح و H1 مخصوص خودش را داشته باشد. این صفحه‌ها همان صفحه‌هایی‌اند که می‌توانند برای جست‌وجوهای خرید رتبه بگیرند.
  • تیترهای سرویس‌ها از H3 به عنصر معمولی تبدیل شوند. تیترها برای ساختار محتوا هستند، نه برای هر ردیف قیمت.
شاهد: دانلود مستقیم صفحه. ۶٬۷۸۷٬۲۱۱ بایت، و با فشرده‌سازی gzip ۲۶۹٬۴۹۱ بایت.

نسخه‌ی http:// سایت جواب نمی‌دهد و HSTS فعال نیست

نشانی‌های http://smmtg.com و http://www.smmtg.com در دو تست از دو شبکه‌ی جداگانه بدون هیچ پاسخی timeout شدند و به https هدایت نشدند. هر کسی که دامنه را بدون https تایپ کند یا روی لینک قدیمی http کلیک کند، به سایت نمی‌رسد. هدر Strict-Transport-Security هم روی نسخه‌ی https وجود ندارد.

راه‌حل (nginx، نیاز به دسترسی سرور): پورت ۸۰ باز شود و با 301 به https برود: 
server {
  listen 80;
  server_name smmtg.com www.smmtg.com;
  return 301 https://smmtg.com$request_uri;
}
# در بلوک https:
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
پیشنهاد: بعد از اصلاح، این مورد را از جاهای مختلف دوباره تست کنیم، چون ممکن است فایروال میزبان پورت ۸۰ را برای بعضی کشورها بسته باشد.

هیچ صفحه‌ای برای کلمات کلیدی خرید وجود ندارد

صفحه‌ی اصلی ۲۹۰ کلمه دارد و H1 آن فقط نام برند است («SMM TG»). وبلاگ فقط ۱ مقاله دارد (به انگلیسی، منتشرشده در ۲۷ اکتبر ۲۰۲۶). برای جست‌وجوهایی که کاربر واقعی با آن‌ها دنبال این خدمات می‌گردد، مثل «خرید ممبر تلگرام» یا «buy telegram members»، هیچ صفحه‌ی اختصاصی‌ای نیست. بدون این صفحه‌ها گوگل دلیلی برای نشان دادن سایت در این جست‌وجوها ندارد.

راه‌حل: برای هر سرویس پرفروش یک صفحه‌ی فرود ساخته شود، با ۶۰۰ تا ۱۰۰۰ کلمه محتوای مفید: نوع سرویس‌ها، قیمت از چند، سرعت شروع، گارانتی و ریفیل، سؤالات متداول و دکمه‌ی سفارش. هر صفحه به سه زبان فارسی، عربی و انگلیسی باشد. H1 صفحه‌ی اصلی هم توصیفی شود، مثلاً «پنل SMM ارزان برای تلگرام، اینستاگرام و تیک‌تاک». فهرست پیشنهادی کلمات در بخش «کلمات کلیدی» آمده است.

اولویت متوسط اصلاحاتی که اعتماد و کیفیت را بالا می‌برند

نسخه‌ی فارسی فقط نیمه‌ترجمه است

در ?lang=fa منوها و صفحه‌ی اصلی فارسی هستند، اما مقاله‌ی وبلاگ کاملاً انگلیسی مانده و عنوانش هم انگلیسی است. نام همه‌ی سرویس‌ها و دسته‌ها در لیست قیمت هم انگلیسی است. گوگل صفحه‌ای که lang="fa" دارد ولی محتوایش انگلیسی است را صفحه‌ی فارسی باکیفیتی نمی‌بیند، و کاربر فارسی‌زبان هم اعتماد نمی‌کند.

راه‌حل: نام دسته‌های اصلی (حداقل ۵۰ دسته‌ی پرفروش تلگرام و اینستاگرام) و مقاله‌ی وبلاگ ترجمه شوند. تا وقتی ترجمه کامل نشده، نسخه‌ی فارسی مقاله از sitemap و hreflang حذف شود.

نام دسته‌ها غلط املایی دارد و ساختارش به‌هم‌ریخته است

اولین دسته‌ی لیست قیمت «Telegram - Premium Mmebers ( New Prices )» است. دسته‌ای با نام «Updateing» هم هست، دسته‌هایی که فقط خط جداکننده‌اند («-------»)، و هم «YouTube» و هم «Youtube» به‌صورت جدا. اولین تیتر H3 صفحه هم «No services found» است. این‌ها روی اعتماد کاربری که برای اولین بار لیست قیمت را می‌بیند اثر منفی دارند.

راه‌حل: نام دسته‌ها اصلاح و یکدست شود، دسته‌های جداکننده حذف شوند و پیام «No services found» تا وقتی نتیجه‌ی جست‌وجو خالی نیست پنهان بماند. این‌ها در پنل مدیریت و بدون نیاز به برنامه‌نویسی انجام می‌شوند.

کش مرورگر برای فایل‌های خود سایت تنظیم نشده است

فایل‌های /public/*.css، tg-plane.png و لوگو هیچ هدر Cache-Control ندارند. کاربری که برمی‌گردد، هر بار حدود ۳۱۳ کیلوبایت را دوباره دانلود می‌کند. فایل‌های CDN پنل درست کش می‌شوند (یک سال).

location ~* \.(png|jpe?g|webp|svg|css|js|woff2)$ {
  add_header Cache-Control "public, max-age=2592000";
}

۳ خطای جاوااسکریپت روی صفحه‌ی اصلی

Lighthouse این خطاها را ثبت کرده است: MutationObserver.observe روی عنصر #srv-desc که در صفحه‌ی اصلی وجود ندارد (خط ۸۳۱)، و دو خطای null در فایل 1cdlbqmm1i66bxpc.js. اسکریپت‌های مخصوص صفحه‌ی سفارش روی همه‌ی صفحات اجرا می‌شوند.

const t = document.getElementById('srv-desc');
if (t) observer.observe(t, { childList: true, characterData: true, subtree: true });

مقاله‌ی وبلاگ ۲٬۲۷۱ کلمه دارد ولی هیچ زیرتیتری ندارد

مقاله‌ی «What Is an SMM Panel?» حتی یک H2 یا H3 ندارد و همه‌اش پاراگراف پشت سر هم است. عنوانش هم برند را دو بار تکرار می‌کند: «… | SMMTG | SMM TG». گوگل از زیرتیترها برای فهم موضوع و ساختن snippet استفاده می‌کند.

راه‌حل: هر بخش یک H2 بگیرد. یک فهرست مطالب و لینک داخلی به صفحه‌ی Services و صفحه‌های سرویس اضافه شود، و عنوان به «What Is an SMM Panel? How It Works | SMM TG» اصلاح شود.

نشان امتیاز Trustpilot به هیچ‌جا لینک نمی‌شود

در فوتر همه‌ی صفحات «4.7/5، 1257 ratings» با لوگوی Trustpilot آمده، اما لینکش href="#" است. کاربر نمی‌تواند این امتیاز را بررسی کند، و برای کاربر حرفه‌ای این ادعای تأییدنشده اعتماد را کم می‌کند، نه زیاد. کپی‌رایت هم هنوز «© 2025» است.

راه‌حل: اگر صفحه‌ی Trustpilot واقعی دارید، به آن لینک شود. اگر ندارید، نشان برداشته شود و به‌جایش چیزی گذاشته شود که قابل بررسی است، مثل لینک کانال تلگرام با تعداد عضو یا نظرات واقعی مشتری‌ها. سال کپی‌رایت هم خودکار شود.
